# ЧАСТЬ I. ОБЩИЕ ПОЛОЖЕНИЯ

## 1. Назначение системы

DentalLocal — настольная информационная система управления стоматологической практикой одного врача. Система предназначена для:

- ведения электронных карточек пациентов с полной историей лечения;
- планирования и фиксации посещений;
- ведения интерактивной зубной формулы (dental chart) по системе FDI;
- учёта финансов: стоимость лечения, оплаты, долги;
- аналитики и статистики работы клиники;
- надёжного локального хранения данных с автоматическим резервным копированием.

## 2. Ключевые ограничения и принципы

| № | Ограничение | Следствие для реализации |
|---|---|---|
| O-1 | Работа только на одном ноутбуке (Windows 10/11 x64) | Нет сетевой синхронизации, нет мультиустройственности |
| O-2 | Полное отсутствие интернета | Все ресурсы (шрифты, иконки, JS-библиотеки) поставляются в составе приложения; никаких CDN |
| O-3 | Один пользователь — врач-администратор | Нет таблицы пользователей с ролями; единственный код доступа |
| O-4 | Запуск одним двойным кликом по EXE | Собственный лаунчер, который поднимает PostgreSQL, backend и открывает UI |
| O-5 | Потеря данных недопустима | Ежедневный автоматический бэкап + бэкап перед обновлением + ручной экспорт/импорт + проверка целостности |
| O-6 | История пациента неудаляема | На уровне домена и БД запрещено физическое удаление записей истории; только «мягкая» архивация с аудитом |

## 3. Глоссарий

| Термин | Определение |
|---|---|
| Пациент (Patient) | Физическое лицо, зарегистрированное в системе, имеющее карточку |
| Посещение (Visit) | Факт приёма пациента врачом в конкретную дату/время |
| Процедура (Procedure) | Услуга из каталога (пломба, удаление и т.д.) с ценой и длительностью |
| Позиция лечения (TreatmentItem) | Конкретная процедура, выполненная в рамках посещения, возможно привязанная к зубу |
| Зубная формула (Dental Chart) | Интерактивная схема 32 зубов по нумерации FDI с состояниями |
| Долг (Debt) | Неоплаченный остаток по посещению |
| Оплата (Payment) | Факт внесения денег (полная или частичная) |
| Бэкап (Backup) | Файл резервной копии БД в формате `pg_dump` custom format (`.backup`) |
| Лаунчер (Launcher) | EXE-приложение, которое запускает все компоненты системы |

# ЧАСТЬ II. АРХИТЕКТУРА

## 4. Технологический стек

**Backend:** C# 13, .NET 9, ASP.NET Core Minimal API + MediatR (CQRS).
**Frontend:** Blazor WebAssembly (.NET 9), hosted-модель (раздаётся backend'ом).
**СУБД:** PostgreSQL 16 (portable-сборка, поставляется вместе с приложением).
**ORM:** Entity Framework Core 9 + Npgsql.
**Библиотеки:** FluentValidation 11, AutoMapper 13, Serilog (файловый sink с ротацией), MediatR 12, MudBlazor 7 (UI-компоненты, кастомизированная тема), ApexCharts.Blazor (графики, офлайн-бандл).
**Паттерны:** Clean Architecture, CQRS, Repository + Unit of Work, Result Pattern, Global Exception Handling, SOLID/DRY/KISS.

## 5. Структура решения

```
DentalLocal.sln
├── src/
│   ├── DentalLocal.Domain            // Сущности, Value Objects, доменные события, енумы, интерфейсы репозиториев
│   ├── DentalLocal.Application       // CQRS (Commands/Queries/Handlers), DTO, валидаторы, мапперы, Result, интерфейсы сервисов
│   ├── DentalLocal.Infrastructure    // Файловое хранилище, бэкапы (pg_dump/pg_restore), Serilog, системные сервисы
│   ├── DentalLocal.Persistence       // DbContext, конфигурации EF, миграции, репозитории, UnitOfWork, сидинг
│   ├── DentalLocal.Server            // ASP.NET Core host: Minimal API endpoints, middleware, DI-композиция, раздача Blazor
│   ├── DentalLocal.Client            // Blazor WASM: страницы, компоненты, сервисы HTTP, состояние
│   ├── DentalLocal.Shared            // DTO-контракты, енумы, константы, общие для Client и Server
│   └── DentalLocal.Launcher          // WinForms/WPF-лаунчер: запуск PostgreSQL, backend, splash-screen, трей-иконка
├── tests/
│   ├── DentalLocal.Domain.Tests
│   ├── DentalLocal.Application.Tests
│   └── DentalLocal.Integration.Tests // Testcontainers/локальный PG
└── docs/                             // Архитектура, ER, UML, руководство пользователя
```

**Правила зависимостей (строго):**
- Domain не зависит ни от чего.
- Application → Domain.
- Persistence → Application, Domain.
- Infrastructure → Application, Domain.
- Server → Application, Infrastructure, Persistence, Shared.
- Client → Shared.
- Shared не зависит ни от чего.
- Циклические зависимости запрещены; проверяются архитектурными тестами (NetArchTest).

## 6. Поток выполнения запроса

```
Blazor Client → HttpClient → Minimal API endpoint → MediatR (Command/Query)
→ FluentValidation (pipeline behavior) → Handler → Repository/UnitOfWork
→ EF Core → PostgreSQL → Result<T> → DTO (AutoMapper) → JSON → Client
```

Pipeline behaviors MediatR (в порядке выполнения): LoggingBehavior → ValidationBehavior → TransactionBehavior (для команд) → PerformanceBehavior (лог запросов > 500 мс).

## 7. Result Pattern и обработка ошибок

- Все handlers возвращают `Result<T>` / `Result` с полями: `IsSuccess`, `Error { Code, Message, Type }`.
- Типы ошибок: `Validation`, `NotFound`, `Conflict`, `Forbidden`, `Failure`.
- Endpoint-маппинг: Validation → 400 (ProblemDetails с полями), NotFound → 404, Conflict → 409, Failure → 500.
- Global Exception Handler (middleware): любое необработанное исключение → лог в Serilog c CorrelationId → ProblemDetails 500 без внутренних деталей.
- На клиенте: единый `ApiClient`-обёртка разбирает ProblemDetails и показывает MudSnackbar с человекочитаемым сообщением на русском.

## 9. Таблицы (PostgreSQL, схема `dental`)

Все таблицы: `id UUID PK DEFAULT gen_random_uuid()`, `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz`. Naming: snake_case.

| last_name / first_name / middle_name | varchar(100) / varchar(100) / varchar(100) NULL | last+first NOT NULL |
| gender | smallint | 1=муж, 2=жен |
| birth_date | date NOT NULL | возраст вычисляется на лету |
| phone | varchar(20) NOT NULL | нормализованный формат +992… |
| phone_extra | varchar(20) NULL | |
| address | varchar(300) NULL | |
| allergies | text NULL | |
| chronic_diseases | text NULL | |
| comments | text NULL | комментарии администратора |
| doctor_notes | text NULL | заметки врача |
| photo_file_id | uuid NULL FK→patient_files | аватар |
| registered_at | timestamptz NOT NULL | дата регистрации |
| last_visit_at | timestamptz NULL | денормализация, обновляется триггером посещения |

**Индексы:** GIN(search_vector); btree(phone); btree(card_number); btree(last_name, first_name); частичный индекс WHERE NOT is_archived.

### 9.2 procedure_categories
`name varchar(100) UNIQUE`, `color varchar(7)` (HEX), `sort_order int`.

Предзаполнение (сидинг): Диагностика (#2196F3), Терапия (#4CAF50), Хирургия (#F44336), Ортопедия (#9C27B0), Ортодонтия (#FF9800), Эндодонтия (#795548), Гигиена и профилактика (#00BCD4), Эстетика (#E91E63).

### 9.3 procedures
`category_id FK`, `name varchar(200)`, `description text`, `price numeric(12,2) NOT NULL CHECK (price>=0)`, `duration_minutes int NOT NULL DEFAULT 30`, `is_active bool DEFAULT true`, `requires_tooth bool DEFAULT false` (нужно ли указывать зуб).

Сидинг ≥ 40 процедур: Осмотр, Консультация, Прицельный снимок, Панорамный снимок (ОПТГ), КТ-диагностика, Анестезия аппликационная/инфильтрационная/проводниковая, Пломба композитная (1/2/3 поверхности), Пломба временная, Лечение кариеса, Лечение пульпита (1/2/3 канала), Лечение периодонтита, Перелечивание канала, Удаление простое, Удаление сложное, Удаление зуба мудрости, Имплантация (установка импланта), Формирователь десны, Коронка металлокерамическая, Коронка циркониевая, Коронка на импланте, Винир керамический, Вкладка культевая, Съёмный протез частичный/полный, Брекеты установка (1 челюсть), Брекеты активация, Элайнеры, Профгигиена (ультразвук + Air Flow), Фторирование, Герметизация фиссур, Отбеливание офисное, Отбеливание домашнее (капы), Шинирование, Лечение стоматита, Снятие коронки, Ретракция десны и др. Все цены редактируемы.

### 9.4 visits
| Поле | Тип |
|---|---|
| patient_id | uuid FK NOT NULL |
| visit_date | date NOT NULL |
| visit_time | time NOT NULL |
| doctor_name | varchar(150) NOT NULL DEFAULT из настроек |
| notes | text | заметки |
| prescriptions | text | назначения |
| materials_used | text | использованные материалы |
| total_cost | numeric(12,2) | Σ позиций, денормализация |
| total_paid | numeric(12,2) | Σ оплат |
| status | smallint | 1=Завершено, 2=Запланировано, 3=Отменено |

**Иммутабельность истории:** DELETE на visits запрещён политикой (`REVOKE DELETE` для рабочей роли + доменное правило: команда удаления посещения не существует). Редактирование заметок разрешено, финансовые поля меняются только через оплаты/позиции с записью в audit_log.

### 9.5 treatment_items
`visit_id FK`, `procedure_id FK`, `tooth_number smallint NULL CHECK (11–18,21–28,31–38,41–48)`, `price numeric(12,2)` (снимок цены на момент лечения), `quantity int DEFAULT 1`, `comment text`.

### 9.6 payments
`visit_id FK`, `patient_id FK`, `amount numeric(12,2) CHECK (amount>0)`, `paid_at timestamptz`, `method smallint` (1=Наличные, 2=Карта, 3=Перевод), `kind smallint` (1=Оплата при лечении, 2=Погашение долга), `note text`. DELETE запрещён; сторнирование — отдельной корректирующей записью с отрицательной ссылкой (`reversal_of_payment_id`).

### 9.7 debts (представление + таблица статусов)
Долг вычисляется: `visit.total_cost − visit.total_paid > 0`. Материализуется таблицей `debts`: `visit_id UNIQUE FK`, `patient_id FK`, `original_amount`, `remaining_amount`, `arose_at timestamptz`, `status smallint` (1=Открыт, 2=Погашен), `closed_at timestamptz NULL`. Обновляется в той же транзакции, что и payments.

### 9.8 tooth_states (актуальное состояние) и tooth_state_history
`tooth_states`: `patient_id FK`, `tooth_number smallint`, `state smallint`, UNIQUE(patient_id, tooth_number).
Енум состояний: 0=Здоров, 1=Кариес, 2=Пломба, 3=Удалён, 4=Коронка, 5=Имплант, 6=Винир, 7=Лечение каналов, 8=Трещина, 9=Разрушен, 10=Пульпит, 11=Периодонтит, 12=Мост, 13=Отсутствует (адентия), 14=Молочный.
`tooth_state_history`: каждая смена состояния → строка: `patient_id`, `tooth_number`, `old_state`, `new_state`, `changed_at`, `visit_id NULL`, `comment`. Удаление запрещено.

### 9.9 patient_files
`patient_id FK`, `file_type smallint` (1=Фото, 2=Рентген, 3=КТ, 4=PDF-документ, 5=Прочее), `file_name`, `content_type`, `size_bytes bigint`, `stored_path varchar(500)` (относительный путь в `Data/Files/{patientId}/{fileId}{ext}`), `uploaded_at`, `description`. Файлы хранятся на диске, в БД — метаданные. Лимит одного файла — 200 МБ (КТ). Допустимые типы: jpg, jpeg, png, webp, bmp, dcm, pdf, zip.

### 9.10 appointments (записи/расписание)
`patient_id FK`, `starts_at timestamptz`, `duration_minutes int`, `procedure_id NULL FK`, `note`, `status` (1=Запланирована, 2=Пришёл→создано посещение, 3=Не пришёл, 4=Отменена), `visit_id NULL FK` (связь после визита).

### 9.11 backup_records
`file_name`, `file_path`, `size_bytes`, `created_at`, `trigger smallint` (1=Ежедневный авто, 2=Перед обновлением, 3=Ручной, 4=Перед восстановлением), `is_valid bool` (проверка `pg_restore --list`), `note`.

### 9.12 audit_log
`occurred_at`, `action varchar(100)` (LOGIN_OK, LOGIN_FAIL, PAYMENT_ADDED, DEBT_CLOSED, BACKUP_CREATED, BACKUP_RESTORED, PATIENT_ARCHIVED, SETTINGS_CHANGED, DATA_EXPORTED …), `entity`, `entity_id`, `details jsonb`. Только вставка.

### 9.13 app_settings
key/value: `access_code_hash` (PBKDF2, 100k итераций, соль; при первом запуске хэшируется код «1998»), `doctor_name`, `clinic_name`, `currency` (по умолчанию TJS, сомони), `theme` (light/dark/system), `backup_time` (по умолчанию 21:00), `backup_retention_days` (по умолчанию 90), `language` (ru).

## 10. Миграции и сидинг
- EF Core Migrations применяются автоматически при старте Server (`Database.Migrate()`), под advisory-lock PostgreSQL, с бэкапом перед миграцией, если БД не пустая.
- Сидинг идемпотентен: категории, каталог процедур, настройки по умолчанию.

# ЧАСТЬ IV. API (Minimal API, префикс /api/v1)

Формат ответов: `application/json`; ошибки — RFC 7807 ProblemDetails. Все списки поддерживают пагинацию `?page=&pageSize=` (по умолчанию 1/25, max 200) и возвращают `{ items, totalCount, page, pageSize }`.

## 11. Перечень endpoints

**Auth**
- `POST /auth/login` `{ code }` → `{ token }` (подписанный локальный токен, срок 12 ч; далее — заголовок `Authorization: Bearer`). Брутфорс-защита: 5 неверных попыток → пауза 30 сек (лог в audit_log).
- `POST /auth/change-code` `{ oldCode, newCode }` — смена кода доступа (мин. 4 символа).

**Dashboard**
- `GET /dashboard/summary` → счётчики: patientsTotal, visitsTotal, incomeToday/Week/Month/Year, debtorsCount, debtsTotal.
- `GET /dashboard/upcoming?days=7` → ближайшие записи.
- `GET /dashboard/recent-patients?count=8`.
- `GET /dashboard/income-chart?period=month|year` — данные для графика.
- `GET /dashboard/procedures-top?count=10`.

**Patients**
- `GET /patients?search=&includeArchived=&page=` — полнотекстовый поиск (tsvector + trigram fallback + поиск по номеру карты и телефону).
- `GET /patients/{id}` — карточка полностью (без тяжёлых коллекций).
- `POST /patients`, `PUT /patients/{id}`, `POST /patients/{id}/archive`, `POST /patients/{id}/unarchive` (физического DELETE нет).
- `GET /patients/{id}/visits`, `GET /patients/{id}/payments`, `GET /patients/{id}/debts`, `GET /patients/{id}/files`, `GET /patients/{id}/teeth`, `GET /patients/{id}/teeth/history`.

**Files**
- `POST /patients/{id}/files` (multipart, стриминг на диск, валидация типа/размера), `GET /files/{fileId}` (отдача с корректным Content-Type, для изображений — миниатюры `?thumb=true`, генерируются и кэшируются), `DELETE /files/{fileId}` — только для файлов, не привязанных к посещению; иначе 409.

**Visits / Treatment**
- `POST /visits` `{ patientId, date, time, notes, prescriptions, materials, items:[{procedureId, toothNumber?, price, quantity, comment}], payment?:{amount, method} }` — атомарно: посещение + позиции + первая оплата + пересчёт долга + обновление состояний зубов (если позиция меняет состояние) + запись tooth_state_history. Транзакция.
- `GET /visits/{id}`, `PUT /visits/{id}/notes` (только текстовые поля).
- `POST /visits/{id}/payments` `{ amount, method, note }` — доплата; amount ≤ остаток; пересчёт долга; если остаток стал 0 → долг закрывается, запись в историю «Долг погашен».

**Procedures**
- CRUD `/procedures`, `/procedure-categories`; деактивация вместо удаления, если процедура использована.

**Teeth**
- `PUT /patients/{id}/teeth/{toothNumber}` `{ state, comment, visitId? }` → обновляет актуальное состояние + пишет историю.
- `GET /teeth/{state}/suggested-procedures` — рекомендованные процедуры для состояния (маппинг в конфигурации: Кариес→[Лечение кариеса, Пломба…], Разрушен→[Коронка, Удаление…] и т.д.).

**Debts**
- `GET /debts?status=open&search=&sort=` — список должников.
- `POST /debts/{visitId}/close` `{ amount, method }` — кнопка «Оплачено»: если amount = остатку → полное погашение; поддерживается частичное.

**Appointments**
- CRUD `/appointments`, `GET /appointments?from=&to=` (для календаря), `POST /appointments/{id}/start-visit` — превращает запись в посещение.

**Analytics**
- `GET /analytics/income?groupBy=day|month|year&from=&to=`
- `GET /analytics/patients?from=&to=` (новые/повторные)
- `GET /analytics/procedures?from=&to=` (топ по количеству и выручке)
- `GET /analytics/debts` (динамика долгов)
- `GET /analytics/average-check?groupBy=month`
- `GET /analytics/load` (загрузка: посещений/день, занятые часы)
- `GET /analytics/export?format=xlsx|csv&report=…` — выгрузка отчёта файлом.

**Backups**
- `GET /backups` — журнал; `POST /backups` — создать сейчас; `POST /backups/{id}/restore` — восстановить (двойное подтверждение, авто-бэкап текущего состояния перед восстановлением); `GET /backups/{id}/download` — экспорт файла; `POST /backups/import` — импорт `.backup` с валидацией `pg_restore --list`.

**Settings**
- `GET /settings`, `PUT /settings`.

**System**
- `GET /system/health` — статус БД, свободное место на диске, размер БД, дата последнего бэкапа.

# ЧАСТЬ V. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС

## 12. Дизайн-система

- **Стиль:** гибрид Material Design 3 + Fluent: карточки со скруглением 16 px, мягкие тени, полупрозрачные glassmorphism-панели (backdrop-blur) для сайдбара и заголовков; минимализм, много воздуха.
- **Типографика:** Inter (кириллица, поставляется локально), заголовки 600/700, базовый размер 14–16 px.
- **Темы:** светлая и тёмная; переключатель в шапке; выбор сохраняется в настройках. Токены цветов: Primary #2E7DF7, Success #22C55E, Warning #F59E0B, Danger #EF4444, поверхность light #F7F8FC / dark #12141A.
- **Анимации:** переходы страниц fade+slide 150–200 мс, hover-эффекты карточек, скелетоны загрузки; всё через CSS, без тяжёлых JS-анимаций.
- **Адаптивность:** брейкпоинты 1440/1200/992/768; на ноутбуке — сайдбар фиксированный, при < 992 — сворачиваемый.
- **Иконки:** Material Symbols (локальный шрифт).
- Все тексты интерфейса — на русском языке.

## 14. Экраны (полное описание)

### 14.1 Экран входа
Центрированная стеклянная карточка: логотип, название клиники, поле «Код доступа» (маскированное, автофокус), кнопка «Войти» (Enter). Ошибка — встряска карточки + красная подпись «Неверный код». После 5 ошибок — таймер обратного отсчёта 30 сек на кнопке.

### 14.2 Дашборд
- Ряд 1 — 4 KPI-карточки: Пациентов всего, Посещений всего, Доход сегодня, Доход за месяц (в каждой — иконка, число, подпись, дельта к прошлому периоду со стрелкой ↑/↓).
- Ряд 2: карточка «Доход» (переключатель Неделя/Месяц/Год, area-chart), карточка «Должники» (число, сумма, кнопка «Перейти»).
- Ряд 3: «Ближайшие записи» (список: время, ФИО, процедура, кнопка «Начать приём»), «Последние пациенты» (аватар, ФИО, дата, клик → карточка).
- Ряд 4: «Топ процедур» (горизонтальный bar-chart), «Структура дохода по категориям» (donut).
- Все данные грузятся параллельно, каждая карточка со своим скелетоном.

### 14.3 Пациенты — список
Строка поиска (живой поиск, debounce 300 мс), фильтр «Показать архивных», кнопка «+ Новый пациент». Таблица: № карты, Фото, ФИО, Возраст, Телефон, Последний визит, Долг (красный бейдж, если есть), действия (Открыть). Сортировка по колонкам, пагинация. Пустое состояние с иллюстрацией и CTA.

### 14.4 Карточка пациента
Шапка: фото (клик — загрузка/замена), ФИО, № карты, возраст, пол, телефоны (клик — копирование), бейджи «Аллергии!» (красный, tooltip с текстом) и «Хрон. заболевания» (жёлтый), суммарный долг, кнопки «Редактировать», «Новое посещение», «Записать на приём».
Вкладки:
1. **Обзор** — адрес, комментарии, заметки врача (inline-редактирование), даты регистрации/последнего визита, мини-статистика (визитов, оплачено всего, долг).
2. **Зубная формула** — интерактивная схема (см. 14.5).
3. **История посещений** — вертикальная таймлайн-лента: карточка визита (дата, время, врач, список процедур с зубами и ценами, итого, оплачено, остаток, заметки, назначения, материалы, вложенные фото/рентген превью). Кнопка «Добавить оплату» при остатке > 0. Записи нельзя удалить — только раскрыть.
4. **Финансы** — таблица всех оплат (дата, сумма, способ, тип, к какому визиту) + история долгов (возник/погашен).
5. **Файлы** — грид карточек с превью (фото/рентген/КТ/PDF), фильтр по типу, drag-and-drop загрузка, просмотрщик изображений (лайтбокс с зумом), PDF открывается во встроенном viewer.

### 14.5 Зубная формула (интерактивная модель зубов)
- SVG-схема 32 зубов в анатомической раскладке FDI (2 дуги: верхняя 18–11|21–28, нижняя 48–41|31–38), реалистичные формы зубов (резцы/клыки/премоляры/моляры), лёгкий 3D-эффект (градиенты, тени), плавный hover-scale.
- Цветовая легенда состояний (Здоров — белый, Кариес — коричневый, Пломба — синий, Удалён — контур пунктиром, Коронка — золотой, Имплант — серый металлик, Винир — фиолетовый, Каналы — оранжевый, Трещина — жёлтый с иконкой, Разрушен — красный и т.д.).
- Клик по зубу → боковая панель: номер и название зуба, текущее состояние, селектор нового состояния, комментарий, блок «Рекомендуемые процедуры» для выбранного состояния (клик — добавляет в черновик нового посещения), история изменений этого зуба.
- Все изменения пишутся в tooth_state_history и видны в истории пациента.
- Переключатель «Взрослая/Молочная формула» (20 зубов, FDI 55–85).

### 14.6 Новое посещение (мастер)
Шаг 1: дата/время (по умолчанию сейчас), заметки, назначения, материалы.
Шаг 2: добавление процедур — поиск по каталогу с цветными категориями; для процедур с requires_tooth — выбор зуба на мини-формуле; редактируемая цена и количество; итоговая сумма пересчитывается живо.
Шаг 3: оплата — «Полностью / Частично / В долг», сумма, способ; превью остатка.
Кнопка «Сохранить посещение» — одна транзакция; успех → возврат в карточку с уведомлением.

### 14.7 Должники
Таблица: ФИО (ссылка), Телефон, Дата лечения, Стоимость, Оплачено, Остаток (красным), Дата возникновения, Дней в долгу. Сортировка по остатку/давности, поиск, итоговая строка «Всего долгов: N на сумму X». Кнопка «Оплачено» в строке → диалог: сумма (по умолчанию весь остаток), способ оплаты, подтверждение. Полное погашение → строка исчезает с анимацией, в историю пациента добавляется запись «Долг погашен: дата, время, сумма, способ». Частичное → остаток обновляется.

### 14.8 Записи (календарь)
Недельная сетка 8:00–20:00 + месячный обзор. Создание записи кликом по слоту: пациент (поиск/быстрое создание), процедура, длительность, заметка. Карточка записи цветом категории процедуры. Действия: «Пациент пришёл» (→ мастер посещения с предзаполнением), «Не пришёл», «Отменить», перенос drag-and-drop. Конфликты слотов подсвечиваются.

### 14.9 Процедуры (каталог)
Группировка по категориям (цветные секции, сворачиваемые). Таблица: название, описание, цена, длительность, активна. CRUD в диалогах, управление категориями (название, цвет — color-picker, порядок). Массовое изменение цен (+N %).

### 14.10 Аналитика
Фильтр периода (пресеты: Сегодня/Неделя/Месяц/Квартал/Год/Всё время/Произвольный). Секции: Доход (area, day/month/year), Новые vs повторные пациенты (stacked bar), Топ-10 процедур (bar + таблица с выручкой), Долги (динамика + текущие), Средний чек (line), Загрузка клиники (heatmap по дням недели/часам), Доход по категориям (donut). Кнопка «Экспорт» → XLSX/CSV выбранного отчёта.

### 14.11 Резервные копии
Статус-карточка: последний бэкап (дата, размер, «✓ проверен»), следующий по расписанию, свободное место на диске. Кнопки: «Создать копию сейчас», «Импортировать файл». Таблица копий: дата, тип (Ежедневная/Перед обновлением/Ручная), размер, валидность, действия: «Экспортировать» (сохранить куда угодно через диалог), «Восстановить». Восстановление: модальное окно с красным предупреждением, чекбокс «Я понимаю, что текущие данные будут заменены», ввод слова «ВОССТАНОВИТЬ»; процесс: авто-бэкап текущего состояния → restore → перезапуск подключения → отчёт. Настройки: время ежедневного бэкапа, срок хранения, дополнительная папка-зеркало (например, флешка/OneDrive-папка).

### 14.12 Настройки
Имя врача, название клиники, валюта, тема, время бэкапа, смена кода доступа (старый + новый + повтор), путь к папке данных (только просмотр), версия приложения, кнопка «Открыть папку логов».

## 15. Сквозные UX-правила
- Все разрушающие действия — подтверждение диалогом.
- Все операции > 300 мс — индикатор загрузки; кнопки блокируются на время запроса (защита от даблкликов).
- Уведомления: MudSnackbar (успех — зелёный, ошибка — красный, 4 сек).
- Формы: валидация на лету (FluentValidation-правила продублированы в Shared и переиспользуются на клиенте), ошибки под полями на русском.
- Горячие клавиши: Ctrl+K — поиск, Ctrl+N — новый пациент, Esc — закрыть диалог.

# ЧАСТЬ VI. КЛЮЧЕВЫЕ СЦЕНАРИИ (Use Cases)

**UC-1. Первый запуск.** Двойной клик по EXE → лаунчер: splash «Инициализация…» → распаковка/initdb portable PostgreSQL (если нет кластера) → запуск pg на 127.0.0.1:5544 → запуск backend на 127.0.0.1:5188 → миграции + сидинг → открытие окна приложения (WebView2 либо браузер по умолчанию на http://127.0.0.1:5188) → экран входа → код 1998 → дашборд (пустые состояния с подсказками «Добавьте первого пациента»).

**UC-2. Приём пациента с частичной оплатой.** Поиск пациента → карточка → «Новое посещение» → процедуры: Лечение пульпита (зуб 36, панель формулы: состояние 36 → «Лечение каналов») + Пломба → итог 900 → оплата «Частично» 500 наличными → сохранение. Результат: визит в истории, долг 400 в «Должниках», зуб 36 перекрашен, история зуба пополнена, дашборд обновлён.

**UC-3. Погашение долга.** Раздел «Должники» → строка пациента → «Оплачено» → сумма 400, способ «Карта» → подтверждение → долг исчезает, в истории пациента запись «Долг погашен — 13.07.2026 18:42, 400 TJS, карта», audit_log пополнен.

**UC-4. Ежедневный бэкап.** 21:00, приложение работает → фоновый HostedService: `pg_dump -Fc` → файл `Backups/backup_2026_07_13_2100.backup` → `pg_restore --list` проверка → запись в backup_records → копия в папку-зеркало (если настроена) → удаление копий старше retention → индикатор в шапке обновлён. Если ноутбук был выключен в 21:00 — бэкап выполняется при следующем запуске (catch-up).

**UC-5. Восстановление.** Настройки бэкапов → выбор копии → подтверждения → авто-бэкап текущего → `pg_restore --clean --if-exists` → успех → уведомление и мягкая перезагрузка UI. Ошибка → автоматический откат на авто-бэкап, отчёт пользователю, лог.

**UC-6. Запись на приём → визит.** Календарь → слот завтра 10:00 → выбор пациента → сохранение. Завтра: дашборд «Ближайшие записи» → «Начать приём» → мастер посещения с предзаполненной процедурой → сохранение → запись получает статус «Пришёл» и связь с визитом.

# ЧАСТЬ VII. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

## 16. Производительность
- Холодный старт системы (лаунчер → экран входа): ≤ 10 сек; тёплый: ≤ 5 сек.
- Поиск пациента среди 50 000 записей: ≤ 150 мс (tsvector + pg_trgm).
- Открытие карточки пациента: ≤ 300 мс; дашборд: ≤ 500 мс (параллельные запросы + кэш summary 30 сек, инвалидация при записи).
- Все запросы EF — `AsNoTracking` для чтения, проекции в DTO, `Include` только необходимого; N+1 запрещён (интеграционные тесты с подсчётом SQL).
- Blazor WASM: AOT не используется (размер), включены trimming и Brotli-предкомпрессия; ленивые сборки для страницы аналитики.

## 17. Безопасность
- Backend слушает только 127.0.0.1; PostgreSQL — только 127.0.0.1, пароль генерируется при первой установке и хранится в DPAPI-защищённом файле конфигурации.
- Код доступа — только PBKDF2-хэш; в логи не попадает.
- Валидация всех входных данных (FluentValidation) + параметризованные запросы EF (SQL-инъекции исключены).
- Загрузка файлов: whitelist расширений, проверка сигнатур (magic bytes), сохранение под GUID-именами, никакого исполнения.
- Логи Serilog: `Data/Logs/log-.txt`, ротация по дню, 30 дней; уровни: Information (действия), Warning, Error c stack trace и CorrelationId; персональные данные в логах минимизированы.
- Аудит критических операций — таблица audit_log.

## 18. Надёжность и восстановление
- Лаунчер контролирует процессы: падение backend → автоперезапуск (до 3 раз) с записью в лог; падение PostgreSQL → корректный рестарт; при невозможности — диагностическое окно с кнопкой «Открыть логи».
- Грациозное завершение: закрытие окна → остановка backend → `pg_ctl stop -m fast` → гарантированный flush WAL.
- PostgreSQL: `fsync=on`, WAL по умолчанию — устойчивость к сбоям питания.
- Health-check при старте: доступность БД, свободное место (< 2 ГБ — предупреждение), возраст последнего бэкапа (> 48 ч — предупреждение).

## 19. Состав поставки
```
DentalLocal/
├── DentalLocal.exe          // Лаунчер (self-contained, single-file)
```

Установка = копирование папки. Первый запуск выполняет initdb автоматически. Обновление = замена `app/` и `DentalLocal.exe`; лаунчер перед применением новой версии (сравнение версий) делает бэкап типа «Перед обновлением».

## 20. Лаунчер
WPF, single-file EXE. Функции: splash-screen с этапами; поиск свободных портов при конфликте; single-instance (mutex — второй запуск активирует окно); значок в трее (Открыть, Создать бэкап, Выход); встроенное окно WebView2 (если WebView2 Runtime отсутствует — fallback на браузер по умолчанию); мониторинг дочерних процессов; корректная остановка всех компонентов при выходе.
