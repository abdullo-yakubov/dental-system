# teeth-model-generator

Процедурный генератор анатомической 3D-модели зубного ряда для DentalLocal
(разделы 8/17.3/19.7/21.5 ТЗ). Запускается один раз при разработке; результат
(`.glb` + `.meta.json`) коммитится в `src/DentalLocal.Client/wwwroot/models/`.
В рантайме приложения геометрия никогда не строится — только загружается готовый `.glb`.

## Запуск

```powershell
npm install
node src/index.js --adult --child --check --out ../../src/DentalLocal.Client/wwwroot/models
```

Флаги:
- `--adult` — постоянный прикус (32 зуба, `teeth.glb`)
- `--child` — молочный прикус (20 зубов, `teeth-deciduous.glb`)
- `--check` — печатает диагностику (число вершин/треугольников, NaN/Inf, углы дуги,
  карту рельефа зуба 16) без записи файлов, если `--out` не указан
- `--out <dir>` — директория для записи `.glb`/`.meta.json`; без него — только диагностика

Без `--adult`/`--child` обрабатываются оба прикуса.

После генерации стоит прогнать `gltf-validator` (dev-зависимость):

```js
import { readFile } from 'node:fs/promises';
import { validateBytes } from 'gltf-validator';
const report = await validateBytes(new Uint8Array(await readFile('teeth.glb')));
console.log(report.issues);
```

## Файлы

- `src/anatomy.js` — таблицы размеров/бугров/дуг постоянного и молочного прикуса (§4 промта)
- `src/arch.js` — решатель углов установки зубов по дуге (§5.5)
- `src/geometry.js` — построение геометрии зуба (§5.1-5.4, 5.6) и десны (§5.7)
- `src/export.js` — расстановка по дуге, сборка glTF-документа, метаданные (§6)
- `src/index.js` — CLI

## Известные допущения (данные заданы не полностью)

- **pw/squash/tilt для молочных зубов**: таблица §4 задаёт для молочных зубов только
  md/bl/ch/rl/roots. Значения pw/squash/tilt взяты по аналогии с одноимённым классом
  постоянного зуба (резец/клык/моляр) — в промте эти числа не заданы явно.
- **Бугры молочных моляров (позиции 4-5)**: по тексту промта эти позиции — m1/m2
  (молочные моляры), поэтому им назначены бугорковые карты соответствующих постоянных
  моляров (`MOLAR_U` сверху, `MOLAR_L4`/`MOLAR_L5` снизу), а не `PREMOLAR`, несмотря на то
  что позиционно они стоят на месте будущих премоляров.
- **Смещение корней для молочных многокорневых зубов**: §4 промта явно задаёт формулы
  смещения корней только для конкретных постоянных зубов (3-корневой верхний моляр,
  2-корневой верхний премоляр/восьмёрка, 2-корневой нижний моляр). Для молочных
  многокорневых зубов использованы те же безразмерные формулы по числу корней и челюсти
  (все молочные многокорневые — моляры, поэтому неоднозначности "премоляр vs восьмёрка"
  для них не возникает).
- **`mesialAxis`**: абсолютная привязка "+X = мезиально" — собственное соглашение
  генератора (в исходных бугорковых таблицах жёсткой стороны не задано). Немирроренная
  ("базовая") геометрия каждой позиции получает `mesialAxis: "+X"`, зеркальная — `"-X"`;
  соглашение внутренне согласовано для обеих сторон дуги.
- **Послойный цвет коронки** (§5.4) делит коронку на трети высоты (шейка/тело/режущий
  край); численный порог перехода корень→верхушка взят как доля длины корня (0 у шейки,
  1 у верхушки), т.к. точная формула в промте не указана.

## Контрольные углы дуги (§5.5) — расхождение по верхней дуге

`--check` подтверждает решатель формулой `2a·sinθ₁ = md₁·1.02` для первого зуба и
"минимальный угол, при котором хорда между центрами ≥ (md_i+md_{i+1})/2 + 0.15" для
последующих — **буквально** как написано в §5.5.

Для **нижней** дуги это воспроизводит контрольные углы из промта почти точно
(макс. отклонение 0.234° < 0.3°) — решатель подтверждён как корректный.

Для **верхней** дуги результат расходится с контрольными числами (до ~4°). Проверка:
хорда между уже данными в промте контрольными углами верхней дуги (a=27, b=42) —
меньше `avgMd`, тогда как по формуле §5.5 она должна быть `avgMd + 0.15` (что подтверждает
нижняя дуга с той же формулой). То есть контрольная таблица верхней дуги в промте не
согласуется с приведённым в нём же алгоритмом — либо таблица содержит опечатку/округление,
либо использовался другой набор констант именно для верхней дуги. Решатель оставлен
буквальным (не подогнан "на глаз" под несогласованные контрольные числа); при появлении
уточнённой формулы/констант для верхней дуги — поправить `arch.js`.
